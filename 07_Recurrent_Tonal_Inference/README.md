# 07_Recurrent_Tonal_Inference

Working copy for the recurrent-modeling continuation of the tonal inference project. Everything in here is a **copy** — the originals in the parent "Tonal Inference Modeling - Claude" folder were not moved, renamed, deleted, or edited to create this workspace.

## 1. COGS 269 — static feed-forward foundation

`01_Prior_Work_Context/Emergent Tonal Structure from a Simple Neural Network.pdf` is the original COGS 269 work: a feed-forward MLP (`ChordToKeyMLP`, 24 → 48 → 24) trained on synthetic diatonic triads to predict key from a single chord. No time dimension — one chord in, one key-probability distribution out. This is the static building block everything since has been layered on top of.

## 2. COGS 202 — completed prior work (MLP + hand-coded EMA/leaky integration on MIDI)

`01_Prior_Work_Context/Emergent Tonal Inference - Triadic Model and Melodies.pdf` is the completed, already-presented COGS 202 paper. It extends the COGS 269 MLP to real MIDI by adding *hand-coded* temporal smoothing at two separate levels, both implemented in `02_Baseline_Pipeline/Mini Capstone_Project_A_walking_machine_of_the_music.ipynb`:

- Chroma-level exponential moving average (`midi_to_chord_ids`, `memory_decay = 0.6`) smooths the raw chroma window before it's template-matched to a chord.
- Hidden-state leaky integration (`sequence_key_tracking`, `alpha` parameter) manually blends the MLP's instantaneous hidden activation with the previous timestep's hidden state: `h = (1 - alpha) * h + alpha * h_in`.

Both are fixed, untrained scalars (`memory_decay`, `alpha`) chosen by hand — there is no learned temporal component anywhere in this pipeline. This milestone is done; it is not the current work.

## 3. Current goal: EMA/leaky-memory baseline vs. a learned recurrent hidden state

The open question this workspace exists for: replace or compare the hand-coded leaky integration in `sequence_key_tracking` with an Elman-style SRN whose hidden-state update (`W_ih`, `W_hh`) is learned end-to-end on labeled chord sequences, instead of hard-coded via `alpha`. `04_Recurrent_Implementation/` is where that code goes — it's currently empty. MIDI parsing, chroma extraction, key labeling, and the Circle-of-Fifths/probability-tracking plots from the existing notebook are expected to carry over unchanged; only the temporal-memory mechanism is being swapped out.

## 4. The two historical PNGs in `05_Figures_Results/` are mislabeled

`HISTORICAL_MISLABELED_actually_Mozart12_Prob_Tracking.png` and `HISTORICAL_MISLABELED_actually_Mozart12_CircleOfFifths.png` were generated by the notebook's cell that loads `Twinkle 12.mid` (Mozart's 12 Variations — 2 tracks, 6,294 notes, real embedded key-signature changes at ≈384s and ≈432s) but titles its plots "Twinkle Twinkle." Confirmed by inspecting the images directly: the probability-tracking plot's x-axis runs to ~1270 windows (matches Mozart's ~687s run length, not Twinkle's ~53s), and the Circle-of-Fifths walk shows the wide, erratic jumps the COGS 202 paper describes for its Mozart/"ornamentation collapse" condition, not the stable, clustered trajectory it describes for the true Twinkle condition. These two files are preserved here for reference only — do not treat them as the Twinkle baseline.

## 5. True Twinkle.mid baseline figures are missing — regenerate before SRN comparison

The COGS 202 paper describes a stable, clustered Circle-of-Fifths trajectory for `Twinkle.mid` alone (its Figures 4/5), but no standalone figure file for that run exists anywhere in the original folder — it was apparently only ever embedded directly into the exported paper/Google Doc, never saved out as a PNG. Before running any baseline-vs-SRN comparison, regenerate this pair from `03_MIDI_Data/Twinkle.mid` using the existing (unmodified) `midi_to_chord_ids` → `sequence_key_tracking` → `plot_key_tracking`/`plot_fifths_walk` path in `02_Baseline_Pipeline/`, so there's an honest known-good simple case to compare the SRN against — not just the mislabeled Mozart pair.

**Update:** These have now been regenerated locally — see `05_Figures_Results/Twinkle_mid_EMA_MLP_Prob_Tracking.png`, `05_Figures_Results/Twinkle_mid_EMA_MLP_CircleOfFifths.png`, and `05_Figures_Results/Twinkle_mid_EMA_MLP_Baseline_RunNotes.md` for full run details.

Two files were left out of this workspace as optional/tangential references rather than core materials for the recurrent extension:

Relevant as theoretical motivation for why a time-evolving internal state matters, but not an architecture reference the way the TRACX2 paper is. Still in the root folder if needed.
- `clark-chalmers-1998 : Jeff.pdf` — Clark & Chalmers, "The Extended Mind" (1998). Fits a distributed/extended-cognition framing angle but its connection to this project is unconfirmed (filename suggests it came from someone named Jeff rather than being sourced for this work). Still in the root folder if you decide it's relevant later.

## Folder guide

- `01_Prior_Work_Context/` — COGS 269 and COGS 202 papers (completed, non-recurrent background).
- `02_Baseline_Pipeline/` — the working notebook: MIDI parsing, chroma extraction, chord templates, the feed-forward MLP, and the hand-coded EMA/leaky-integration baseline.
- `03_MIDI_Data/` — `Twinkle.mid` (true simple sanity case) and `Twinkle 12.mid` (Mozart, has real embedded modulation timestamps).
- `04_Recurrent_Implementation/` — empty; where the SRN model, labeled synthetic-sequence generator, training loop, and baseline-vs-SRN comparison script will go.
- `05_Figures_Results/` — existing (mislabeled, historical) output figures; also where the regenerated true-Twinkle baseline and any new SRN comparison figures should land.
- `06_Recurrent_Theoretical_References/` — the TRACX2 paper, the closest existing reference to a recurrent connectionist model applied to melody/sequence perception.
- `07_Archive_DoNotEdit/` — the non-canonical Google Docs export of the COGS 202 paper, kept for reference, not to be treated as the citable version.
